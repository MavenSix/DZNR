The stack these prompts recommend

Every prompt names the specific library for the job rather than listing alternatives. This is opinionated on purpose. Swap the recommendation if your team already standardized elsewhere, but assume this stack unless you have a reason not to.

  • Runtime: React Three Fiber (R3F) as primary. Vanilla Three.js when the project has no React.
  • Helpers: @react-three/drei for essential utilities (Environment, OrbitControls, useGLTF, ScrollControls, Text, Html)
  • Physics: @react-three/rapier (WASM, fastest for browser)
  • Post-processing: @react-three/postprocessing (Bloom, DOF, Chromatic Aberration, Noise)
  • Character controllers: ecctrl for third-person, or PointerLockControls for first-person
  • Scroll: GSAP ScrollTrigger for cinematic scenes, drei ScrollControls for scene-embedded pages
  • State: Zustand for global scene state, Valtio for reactive object trees
  • UI animation: Motion.dev (formerly Framer Motion) for HTML overlays, R3F built-ins for scene tweens
  • Loaders and tooling: gltfjsx for GLTF-to-component generation, leva for dev-time controls
  • XR: @react-three/xr for VR and AR (Meta Quest, iOS Quick Look fallback)
  • Build: Vite, TypeScript strict mode, tree-shaken production bundles
  • 3D asset pipeline: Blender for authoring, KTX2 + Basis for textures, Draco for geometry compression
The quality contract

What every prompt inherits

The prompts below describe what to build. This describes what “done” means, and it is the difference between a demo and something you can put a client’s name on. Append the block at the end of this section to any prompt in the library.

Accessibility

  • 1.1.1Canvas content is invisible to assistive tech. Nothing you draw in WebGL exists in the accessibility tree. Either mark the canvas aria-hidden="true" when it is decorative, or give it role="img" with an aria-label, and mirror any real content into the DOM.
  • 2.1.1Every interaction needs a keyboard path. Meshes are not focusable. Either overlay real focusable DOM controls positioned over the scene, or use @react-three/a11y with its A11yAnnouncer. Hover-only interactions do not exist for keyboard or touch users.
  • 2.3.3Honour prefers-reduced-motion. Read it with matchMedia and listen for change — users toggle it at runtime. For 3D this rarely means “show nothing”: freeze continuous rotation, camera drift, pointer parallax, and scroll-linked motion, but keep the composed scene. See MDN.
  • 1.4.3Contrast applies to text over a canvas. Overlay copy sits on a moving background; check the worst frame, not the first. Add a scrim if it fails.
  • Motion sickness is the specific risk of this medium. Sustained self-motion, forced camera rotation, and large-field parallax are vestibular triggers. Flythroughs and first-person cameras need a reduced-motion alternative that is not just “slower”.

Production hardening

  • Dispose every GPU resource on teardown. Three.js does not garbage-collect VRAM. Traverse the scene and dispose geometries, materials, textures, and render targets. Verify with renderer.info.memory: mount and unmount ten times, both counters must return to baseline.
  • Gate the render loop. IntersectionObserver for offscreen plus visibilitychange for background tabs. Render one clean frame when you stop.
  • Cap device pixel ratio at Math.min(window.devicePixelRatio, 2). Cost scales with the square of the ratio; a DPR-3 phone renders nine times the pixels on the weakest GPU you ship to. Cap at 1.5 for full-screen post-processing.
  • Handle context loss. Listen for webglcontextlost and call event.preventDefault() — without it webglcontextrestored never fires and the canvas is black permanently.
  • Test on a real mid-range Android, not a throttled desktop tab.

Performance budget

  • Frame budget: 16.6ms at 60fps. State the target device in the prompt, or you will get something tuned for an M-series laptop.
  • Draw calls are usually the ceiling before polygon count. Instance anything repeated.
  • Textures dominate payload. KTX2 + Basis, not PNG. Draco or Meshopt for geometry.
  • Time to first meaningful paint: the page must be readable before the scene loads. Never block content on a GLTF.

Version discipline

  • Name the Three.js revision in the prompt. Colour management changed by default at r152 and lighting units at r155. Code written for r128 renders visibly wrong on r165 — washed out, wrongly exposed — and this is the most common source of “it looked right in the tutorial”.
  • Pin R3F and drei together; drei tracks R3F majors closely.
  • If you copy a component from a catalogue, you inherit its revision. Check before mixing sources in one bundle, or you will ship two copies of Three.js.

Interaction pattern library

Fifteen patterns, and what separates the good ones

Project types tell you what to build. Patterns tell you what it should do. Each entry names the pattern, where it has been done well, how it is actually constructed, the accessibility trap specific to it, and the detail that separates world-class execution from the tutorial version. Combine one pattern with one project prompt below.

P01

Exploded Assembly

A product separates into its component parts as you scroll, holds apart long enough to be read, then reassembles. The canonical “show the engineering” move for hardware, and the one you see most often.

Seen in
Apple’s product pages established the grammar; now standard across hardware, automotive, and component brands.
How it's built
Author the model with named parts and a rest transform per part. Drive a single normalized 0–1 progress value from ScrollTrigger with scrub, then lerp each part from rest to its exploded offset along a per-part vector. Stagger part offsets so they do not all separate on the same frame.
Accessibility
The parts and their names are the content. Ship a real parts list in the DOM beside the canvas — that is the text alternative, and it doubles as SEO. Under reduced motion, jump to the exploded state and hold it rather than animating through.
The tell
World-class: parts have weight — different masses move at different rates, with slight rotational drift and settle. Labels arrive after the part stops, not during. Mediocre: everything translates outward at uniform speed on the same easing curve, and reads as a PowerPoint build.
P02

Inertial Hero Object

One object, rendered live, that responds to scroll and pointer with real physical lag. The entire page is a stage for a single hero.

Seen in
Oryzo by Lusion — inertial product render with Z-axis depth scroll, documented here.
How it's built
Never bind rotation to input directly. Keep a velocity value, add input as acceleration, apply damping per frame, integrate. Scroll drives Z depth rather than rotation so the object approaches the camera instead of spinning.
Accessibility
Pointer-driven parallax is a vestibular trigger. Damp to zero under reduced motion and keep the object statically composed. Focus order must skip the canvas if it carries no interactive semantics.
The tell
World-class: the object overshoots and settles; you feel mass. Lighting responds to the movement. Mediocre: rotation equals cursor position with a lerp factor, giving that weightless rubber-band feel every tutorial produces.
P03

Particle Dispersion Reveal

A form assembles from scattered particles on entry and disperses on exit, with each page section staged as a distinct beat.

Seen in
Shopify Editions — scroll-sequenced product reveal with particle dispersion, staged as entrance / hold / exit per section, documented here.
How it's built
Sample target positions from a mesh surface or texture. Store start, target, and a per-particle random seed in instanced attributes. Interpolate in the vertex shader against a uniform progress value — never on the CPU. One draw call for the whole system.
Accessibility
Pure decoration: mark the canvas aria-hidden="true" and let the real headline live in the DOM behind it. If the particles form words, that text must also exist as selectable markup.
The tell
World-class: the three beats are distinct and the hold is long enough to read. Particles have varied arrival times and a settle. Mediocre: continuous churn with no hold, so nothing is legible and the effect reads as noise.
P04

Cursor Spotlight Reveal

Detail in geometry, lighting, or material exists only where the pointer is. The user uncovers the scene rather than being shown it.

Seen in
Hubtown by Unseen Studio — 3D monolith whose detail is revealed by cursor, Awwwards Site of the Day and Developer Award, documented here.
How it's built
Feed pointer position as a uniform, smoothed over several frames. Use it as the centre of a radial mask driving a second material layer, a light position, or a displacement amplitude. Falloff curve matters more than radius.
Accessibility
Hover-only means non-existent on touch and keyboard. Provide an auto-tour that moves the reveal point on a path when no pointer is present, and expose the underlying content in the DOM.
The tell
World-class: the reveal has inertia and a soft, non-circular falloff; something is genuinely hidden and worth finding. Mediocre: a hard circular mask snapped to raw cursor coordinates, revealing a slightly brighter version of what you already saw.
P05

Alcove Sequence

One self-contained 3D room per catalogue item, navigated as discrete stops rather than a continuous space. Scales to a product line without building a world.

Seen in
Cartier Watches & Wonders by Immersive Garden — six self-contained alcoves, one per timepiece, with an audio score layer, documented here.
How it's built
Each alcove is an isolated scene graph with its own lighting rig, loaded on demand and disposed on exit. Transitions are camera dollies through a neutral corridor, which hides the load. Never hold all alcoves in memory.
Accessibility
Discrete stops are a gift — they map cleanly to routes. Give each alcove a real URL, an <h2>, and prev/next controls that work on keyboard. That alone makes the experience navigable without the 3D.
The tell
World-class: each alcove is lit for its specific object, and the transition conceals loading entirely. Mediocre: one generic room with the model swapped and a fade, so every product looks identically lit and cheap.
P06

Terrain Flythrough

A continuous camera glide over landscape, with atmosphere and fog carrying the depth. Turns a place into something navigable.

Seen in
Explore Primland — cinematic scroll-driven flythrough over real terrain with atmospheric fog, documented here.
How it's built
Camera follows a CatmullRomCurve3 spline with getPointAt on scroll progress; lookAt targets a point further along the same curve so turns anticipate. Exponential fog does the depth work. Terrain from a heightmap with chunked LOD.
Accessibility
Sustained self-motion through a 3D space is the strongest vestibular trigger in this list. Under reduced motion, replace the flythrough with discrete viewpoint cards. This is not optional.
The tell
World-class: the camera banks into turns and the fog is colour-graded to the time of day. Mediocre: a linear dolly at constant altitude with grey linear fog, which reads as a screensaver.
P07

Point-Cloud Morph

One shape becomes another through a cloud of points that never breaks apart — used to connect two concepts visually.

Seen in
A staple of AI, data, and biotech brand sites; the visual argument that X becomes Y.
How it's built
Sample both meshes to identical point counts. Store position A and position B as separate attributes; morph in the vertex shader on a single uniform. Nearest-neighbour matching between the sets removes the chaotic crossover that makes naive morphs look wrong.
Accessibility
Decorative — hide from assistive tech and put the actual claim in text. The two states usually correspond to two words that belong in the DOM anyway.
The tell
World-class: points take curved paths with varied timing and arrive in waves; both end states are legible silhouettes. Mediocre: linear interpolation on identical timing, producing a uniform grey blur through the middle of the transition.
P08

Shared-Element WebGL Transition

A thumbnail becomes the hero image of the next page without the WebGL context ever tearing down. The site stops feeling like a series of documents.

Seen in
Codrops has a full build of this with GSAP, Astro and Barba.js — scroll-revealed WebGL gallery.
How it's built
A single persistent canvas outlives the router. On navigation, read the source and destination DOM rects, animate a textured plane between them, then hand off to the real element. The DOM swaps underneath while the plane covers the seam.
Accessibility
Route changes must still move focus to the new page heading and announce via a live region — a persistent canvas makes it easy to forget the page changed at all for a screen reader user. Under reduced motion, cross-fade instead of flying.
The tell
World-class: the handoff is invisible; you cannot identify the frame where the plane becomes the DOM image. Mediocre: a visible pop at the end as the real image swaps in at a slightly different size or colour space.
P09

Curved Infinite Gallery

A scrolling wall of images bent onto a curved surface, wrapping endlessly, with velocity-driven distortion.

Seen in
Ubiquitous in photography, fashion, and studio portfolios; the default “our work” treatment for WebGL-capable studios.
How it's built
Instanced planes on a cylinder or bezier surface. Modulo the scroll offset for infinite wrap. Feed scroll velocity — not position — into a vertex displacement so the grid stretches under acceleration and relaxes at rest.
Accessibility
This is a list of links. It must exist as a real <ul> of anchors, keyboard-tabbable, with the canvas as presentation. Arrow-key navigation should move the gallery, not just the focus ring.
The tell
World-class: distortion is tied to velocity with an asymmetric settle, and images stay sharp with correct mipmaps and anisotropy. Mediocre: constant curvature with no velocity response, and blurry textures at oblique angles.
P10

Fluid Cursor Displacement

The pointer disturbs a surface — ripples, smearing, heat, or ink — that decays back to rest.

Seen in
Common on agency landing pages and album or film promo sites where the whole viewport is the interaction.
How it's built
A ping-pong pair of render targets holding a velocity or flow field. Each frame: advect the previous state, inject force at the pointer, apply dissipation, then use the field to offset UVs of the display texture. Runs at half resolution and upsamples.
Accessibility
Entirely decorative and entirely pointer-dependent. aria-hidden, plus a static composition that stands on its own when the field is at rest — that rest state is what touch and keyboard users see.
The tell
World-class: dissipation is tuned so trails last about a second and the field has visible internal structure. Mediocre: a symmetric radial blob following the cursor with no advection, which reads as a smudge.
P11

Kinetic 3D Typography

Type as geometry — extruded, shattered, inflated, or flowed along a path — reacting to scroll or pointer.

Seen in
Editorial, music, and event sites where the headline is the entire visual identity.
How it's built
Prefer MSDF text (troika-three-text) over extruded TextGeometry: it stays sharp at any scale and costs a fraction of the geometry. Per-glyph transforms come from instanced attributes so a headline is still one draw call.
Accessibility
1.1.1 The words must exist as real text. Render the headline in the DOM, visually hidden if necessary, and mark the canvas presentational. A headline that only exists as geometry is invisible to search and to screen readers.
The tell
World-class: the typeface is a deliberate choice and the effect respects its letterforms; kerning survives the transformation. Mediocre: a default sans extruded 40 units with a bevel, which is the 2014 look.
P12

Raymarched SDF Hero

A full-viewport fragment shader with no geometry at all — volumetric shapes, infinite repetition, soft shadows, computed per pixel.

Seen in
Developer-tool, crypto, and music sites; anywhere the aesthetic should feel computed rather than modelled.
How it's built
One full-screen triangle. The scene is a distance function; march rays until they hit. Cost scales with pixel count and step count, which is why DPR capping is mandatory here — more than in any other pattern on this list.
Accessibility
Decorative, so hide it. The real risk is 2.3.3: raymarched scenes tend toward continuous drift. Freeze the time uniform under reduced motion — the still frame is usually the most beautiful part anyway.
The tell
World-class: considered lighting with soft shadows and ambient occlusion, and a palette that is not the default IQ rainbow. Mediocre: an unmodified Shadertoy port running at native DPR, melting phone batteries.
P13

Branded Arcade Loop

A tightly-scoped playable game with a leaderboard, built to carry a campaign rather than to be a game product.

Seen in
Lacoste Ace Breaker for Roland-Garros — branded arcade mechanic with leaderboard and real-world rewards, documented here. Messenger, a multiplayer delivery game, took an Awwwards Site of the Day.
How it's built
One mechanic, thirty to ninety seconds per run, difficulty ramp, score, share card. Physics via @react-three/rapier. The leaderboard needs a server and abuse protection — budget for that, it is where these projects actually overrun.
Accessibility
2.1.1 Full keyboard control is not optional for a game. Provide remappable keys, a pause, and no reliance on colour alone for game state. Consider a difficulty or assist option.
The tell
World-class: the mechanic connects to the brand idea and the first run is instantly legible without a tutorial. Mediocre: a generic runner with a logo applied, forgotten in a day.
P14

Live Configurator

Real-time material, colour, and component swapping on a product, with the state reflected in the URL.

Seen in
Automotive, furniture, footwear, and eyewear — the highest commercial-intent pattern in this library.
How it's built
Author one GLTF with named material slots. Swap material properties, never the mesh. Pre-load every texture variant as KTX2 and keep them resident. Serialize the full configuration to query params so a build can be shared and restored.
Accessibility
1.4.1 Swatches must carry text names, not colour alone. Every option needs a real form control — radio group or select — that works without the 3D. Announce changes via a live region, and give the canvas a description that updates with the configuration.
The tell
World-class: correct environment lighting so materials read as physically real; changes settle with a micro-transition instead of popping. Mediocre: flat lighting where leather, matte plastic, and brushed metal all look like the same tinted surface.
P15

Baked Sequence Fallback

Not live 3D at all — a pre-rendered image sequence scrubbed by scroll. The professional escape hatch.

Seen in
Apple has shipped this for years on pages people assume are real-time. It is a deliberate senior choice, not a compromise.
How it's built
Render the sequence offline at the quality you actually want, encode to a scrub-friendly format, then draw frames to a canvas on scroll progress. Preload a window around the current frame and decode ahead.
Accessibility
Far easier to make accessible than live 3D: it is images, so it takes a text alternative naturally and has zero context-loss risk. Under reduced motion, show a single key frame.
The tell
World-class: chosen knowingly because the render quality exceeds anything real-time could reach on the device budget, with frame pacing that never stutters. Mediocre: a 400-frame PNG sequence at 4K that costs 80MB and janks on decode.

A few patterns worth knowing

How to use this library well

Every prompt is opinionated. That is the point.

Each prompt names a specific library for the job (rapier over cannon, R3F over vanilla for React projects, GSAP ScrollTrigger over lenis for cinematic scenes) instead of listing every option. If your team already standardized on something else, swap it. But defaulting to the recommendation gets you shipping faster because these libraries have shown up in real production Three.js work.

Fill in the brackets before you send.

Brackets are placeholders for the specifics that make the prompt yours. A prompt with unfilled brackets produces generic output. A prompt where every bracket has a real answer (brand name, aesthetic reference, performance target, tool preference) produces work you can actually ship.

Set the performance target up front.

Three.js quality drops off a cliff on the wrong device. Every prompt in this library has a bracket for the performance target (target device, target FPS, mobile fallback). Fill it in. The prompt output changes materially between "60fps on M1" and "30fps on mid-range Android." A prototype that runs beautifully on your MacBook and dies on a client's phone is worse than useful.

Combine prompts for compound work.

Real Three.js projects are combinations. A brand landing page might use prompt 04 (lighting), 17 (particle field hero), 44 (post-processing stack), and 46 (mobile optimization) in one build. Chain them by naming the composition: "Apply prompt 04 for lighting, then prompt 17 for the hero, then prompt 44 for the post pass, all mobile-optimized per prompt 46."

Use the prompt as a brief, not a spec.

These prompts work when you feed them to an AI coding assistant (Claude, Cursor, Windsurf), a developer, or an agency. The AI or human turns the brief into implementation. Do not expect the prompt to be the code. Expect it to be the clarity that makes the code good.
